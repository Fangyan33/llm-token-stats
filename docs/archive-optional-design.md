# 明细归档可选设计（不纳入一期）

状态：后续可选方案，修订日期：2026-10-13。当前不交付 archive-worker、归档 PostgreSQL schema、S3/MinIO 部署或归档查询接口；一期仅依赖 Doris 一年明细及日/月汇总。

## 1. 何时采用

一期原始事件按 UTC 请求日期分区，在线保留 365 个日期。日/月汇总独立保留约两年。只有后续需要保存超过一年明细、长期恢复或降低在线存储成本时，才评估归档工作包；归档保存期限、查询时效和对象存储费用届时另行确认。

## 2. 三个可选组件

| 组件 | 后续设计职责 |
| --- | --- |
| 归档任务 | 对完整日期分区导出 Parquet；保留全部类型化字段、规范事件 JSON、冲突版本和 Kafka 坐标；封存并等待已有写入事务结束，校验行数、内容摘要和文件元数据 |
| 归档状态 | 保存批次、分区身份与版本、文件清单、校验和发布状态；每天只指向一个完整成功批次，失败重试不覆盖上一份成功结果 |
| 历史明细查询 | 在认证客户范围内选择在线分区或已发布归档；跨交接边界不重复读取，支持分页；缺失归档覆盖显式返回不可用 |

归档必须保留 NULL、有效零值、原始大整数和 token 来源；冲突标记单独保存并保持查询隔离。归档事件没有正文，不能重新分词，也不能恢复未采集事件。

## 3. 生命周期切换

启用前须先回填并验证预期范围，配置独立存储权限、备份、网络和容量。由归档任务接管清理后，关闭原始表动态过期删除；只能在完整归档及日/月汇总确认可用后删除过期在线分区。未接管时一期仍由 Doris 动态分区按一年清理，两套机制不得同时管理同一表。

发布成功、删除前失败可重试；删除成功、状态回写前失败根据实际分区和批次恢复。线上分区与归档重叠时只选择一种来源。日期分区被重建后不能拿少量回放替换原有完整归档。

## 4. 保留及验收

对象存储生命周期通常按上传日计算，不能直接等同请求日期保留期。后续需确定事件日期与物理对象清理规则，清理失败批次及被替换快照时保护当前已发布批次。

验收包括封存并发写入、内容校验、对象丢失、状态发布失败、删除重试、客户权限、分页交接、恢复和容量压测。该工作包另行排期报价，不计入一期基础人天或一期上线验收。

Doris 可通过 [SELECT INTO OUTFILE](https://doris.apache.org/docs/4.x/data-operate/export/outfile/) 导出、通过 [S3 TVF](https://doris.apache.org/docs/4.x/sql-manual/sql-functions/table-valued-functions/s3/) 查询外部文件；这些能力本身不等于完整归档生命周期已经实现。
